ブログのシステム自体を変更しました。

## WordPressとの決別

WordPressはシェアも大きく実際便利なんですが同時に不満点も多いです。
思いつく限りでも

- PHPが言語的にあまり好きではない
  - カスタマイズ・メンテナンスに難がある
- プラグインあんまり使ってない
  - コメントスパム対策が有料になった
  - ちなみにreCaptchaは一回突破された
- 攻撃が多い
  - コメントの大量スパム
  - 管理画面のアクセス試行
- 単純にエディタが使いづらい
  - Markdownエディタも微妙
  - 一応クラシックに戻すプラグインはある

## レンタルサーバーとの決別

レンタルサーバーにも不満はありました。何度か入れ替えて解決した問題も含まれているのですが、
今まであったレンタルサーバーに対する問題は具体的に以下の通り。

- 格安 / 無料プランの機能制限
  - SSLが設定できない
  - 数ヶ月に一度更新ボタンを押す必要がある
- レガシーな技術が使われている
  - htaccessでのアクセス制御
  - アップロードがFTP通信

## サイトの移行について

そういうわけで、乗り換え先はずっと探していたのですが、
改めて条件を整理するとWordPressもレンタルサーバーもやめたいわけで、
こうなってくるとクラウドのLinuxにnginxでいいんじゃないかな。と思うわけです。

ただし、できればコストはかけたくないのと、乗り換えは容易であってほしいのでそれを含めて選定していきます。

なお、ドメイン管理費はどうにもならないので割り切ります。サーバー契約で無料とかいうまやかしに用はない。

### サーバーの移管

先も言いましたができればLinuxがいいです。無料のVPSは国内に存在しないので、クラウドの無料枠か海外VPSを駆使します。

[Oracle Cloud Infrastructure（OCI）](https://www.oracle.com/jp/cloud/)が無料枠でサーバー2台まで使えますのでこれにします。[^1]

SSL証明書は[Cloudflare](https://www.cloudflare.com/ja-jp/)を使用します。[^2]
このサイトしか運営しないので無料枠で十分です。

[^1]:無料枠はなかなか取れないと云われていますが、従量課金に切り替えたら一瞬で取れました。（この場合も枠内なら無料）
[^2]:Cloudflare 経由で公開することでHTTPS通信になる。副次的にCloudflare DNS使用者のルーティングが早くなったり、CDN設定やDDOS対策もできるのでメリットが多い。

### バックエンドの変更

自作しますので設計を決めます。

どうせ自由に記述するのでWordpressの制約はありません。先の問題は以下の通り解決。

- PHPが言語的にあまり好きではない
  - C#で書きます
- プラグインあんまり使ってない
  - 静的ジェネレーターでよい
- 攻撃が多い
  - コメント欄はアカウント必須とする
  - 管理画面は用意しない
- 単純にエディタが使いづらい
  - MarkdownもVSCodeなら

ASP.NETで作ったREST APIとGitHubの各機能を使って管理するものとします。

#### 更新

1. ブログコンテンツの更新は、GitHub CodespaceのVSCodeで記述。
2. CodespaceでpullするとWebhockでサーバーにREST APIを送信。
3. サーバー側でHTMLファイルを再生成し作業ディレクトリに保存。

#### ホスティング

1. HTMLのGET要求はASP.NET minimal APIで待ち受け
2. 生成されたHTMLを探索し返答
3. ない場合は404

#### 設計について

1. 内容はMarkdownファイルで管理する
   - C# (Razor構文)で大枠のテンプレートを作成
      - カテゴリーページやトップページはテンプレートからC#で生成
      - コンテンツはMarkdownからHtmlに変換
   - 細かいデザインはCSSで設定
   - タイトルなどのメタデータはjsonに記述
   - 変換後のHTMLをホスティングする
2. テンプレートの一部はリビルドなしで編集できるようにする
   - 特にheadはサードパーティのjavascriptタグを挟みたいことが多い
3. GitHubのリポジトリ上で管理
   - 執筆や編集もすべてGitHub Codespaceで行う
   - GitHub Webhockで更新を検知
4. コメント欄を用意するが、認証しないと書き込みできなくする
   - 2に関連し、GitHubのリポジトリのIssueをコメント欄として使う
5. UIの管理画面は必要ない
   - 更新＆再生成はREST APIで行う
   - GitHub WorkhookでGitHubから自動POSTを受ける
   - ただし将来的に追加できるように拡張性は持たせる

## 展望

これを思い立ったのが1/27。そこから記述を開始して約1か月で初版が完成しました。
3/1から実際に入れ替えてみましたが、問題なく動いていそうです。

このあとはこのサイトに特化した部分を修正して、汎用的に使えるものにしてからソースコードも公開して行きたいなと考えてます。
特にRazorで作成したテンプレート部分は完全にソースコードに埋め込んでいるので最低限ここは修正が必要です。

個人開発したものとしては初の中規模アプリになりますので、それなりに使えるものに仕上げたいところです。
